Cube 斜棱线与精确拾取：模块概述与排除规则 (module.cube) ​

dev/26.1独立版本分支文档
Minecraft 版本26.1.2
NeoForge 版本26.1.2.x
Java 要求Java 25+
Maven Artifact 后缀-neoforge-26.1

module.cube（构件名 anvillib-cube-neoforge-26.1，包名 dev.anvilcraft.lib.v2.cube）为包含旋转元素（斜块、机械部件、装饰模型）的方块提供精确射线拾取（Ray Picking）与真实多面体并集斜棱线高亮（Outline Highlight）。

在 Minecraft 原版中，方块的选择框（VoxelShape）只能由轴对齐长方体（AABB）拼成；如果方块 JSON 模型中包含旋转过的 elements（例如 22.5° / 45° 斜撑或 26.1 的三轴欧拉角旋转），原版准星拾取和黑框描边要么退化为粗糙的台阶状 AABB，要么只能用整格方块框住。module.cube 直接在客户端模型烘焙阶段提取 JSON 模型的真实旋转长方体元素，将其转化为闭凸多面体（ConvexShape），构建 BVH 加速结构并在后台线程计算消除共面接缝后的真实外轮廓棱线。

本模块按功能拆分为 3 篇子文档：

  • 本篇（模块概述、事件与目标排除规则）：详解命名空间启用、永久排除、按 ID 可重载的运行时目标排除规则，以及 AnvilLibCube、CubeSelection（配置入口）、CubeHighlightEvents、CubeModelEvents。
  • 精确拾取与动态部件提供器：详解 CubePicking、BlockSelectionProvider（方块实体 BER 活动部件适配）、SelectionPart、CubeSelection.Target 与 OutlineRenderer。
  • 模型捕获、解码与几何轮廓缓存：详解 ModelCapture、CubeModelDecoder、ModelSelection、ModelSelections、ConvexShape、SelectionGeometry、OutlineBuilder、OutlineCache 与 PackedOutline。

一、 接入配置与快速启用 ​

1. Gradle 依赖 ​

若已引入聚合包 anvillib-neoforge-26.1，则已自动包含本模块；若仅需单独引入 cube 模块：

kotlin
dependencies {
    implementation("dev.anvilcraft.lib:anvillib-cube-neoforge-26.1:2.0.0")
}

2. 三步启用模组方块的斜棱线与精确拾取 ​

module.cube 默认不会无差别扫描所有模组的方块，必须由你的模组在**客户端初始化阶段（且在模型烘焙发生前）**调用 CubeSelection.enableNamespace(MOD_ID) 显式启用本模组命名空间：

java
package com.example.mymod.client;

import com.example.mymod.MyMod;
import com.example.mymod.init.ModBlocks;
import dev.anvilcraft.lib.v2.cube.client.CubeSelection;
import net.minecraft.resources.Identifier;
import net.neoforged.api.distmarker.Dist;
import net.neoforged.fml.common.Mod;

@Mod(value = MyMod.MOD_ID, dist = Dist.CLIENT)
public class MyModClient {
    private static final Identifier BLACKLIST_RULE_ID =
        Identifier.fromNamespaceAndPath(MyMod.MOD_ID, "config_blacklist");

    public MyModClient() {
        // 1. 启用本模组命名空间下所有方块的模型精确拾取与斜棱线高亮
        CubeSelection.enableNamespace(MyMod.MOD_ID);

        // 2. （可选）永久排除不需要模型拾取的特定方块（不参与模型几何烘焙）
        CubeSelection.exclude(ModBlocks.SIMPLE_CABLE.get());

        // 3. （可选）注册运行时动态排除规则：随时根据客户端配置或方块状态开关斜棱线，且无需重新烘焙模型
        CubeSelection.registerTargetExclusion(
            BLACKLIST_RULE_ID,
            state -> !MyModClientConfig.INSTANCE.enableFancyOutline
                || state.is(ModBlocks.DEBUG_FRAME.get())
        );
    }
}

3. 数据驱动资源包规则 (assets/<namespace>/anvillib/cube_selection.json) ​

除了 Java API，模组或整合包（如 KubeJS）还可以通过资源包中的 assets/<namespace>/anvillib/cube_selection.json 声明或覆写选取与描边模式，并通过 F3+T 热重载生效：

json
{
  "namespaces": {
    "kubejs": "model"
  },
  "blocks": {
    "kubejs:example": "outline",
    "kubejs:interaction_proxy": "vanilla"
  }
}
  • model：启用精确模型射线拾取与模型斜棱线描边；
  • outline：保留方块原有的碰撞箱射线拾取，仅启用模型斜棱线描边（适合仍需自定义点击箱体、但希望显示精细几何轮廓的方块）；
  • vanilla：完全回退原版选取与描边；
  • 优先级与合并规则：blocks 优先于 namespaces，未配置项保留 Java API（enableNamespace / registerDynamic）注册的默认值；跨资源包按从低到高顺序加载，同一包内按资源 ID 字典序逐键覆盖；若文件存在非法字段、未知模式或非法 Identifier 则记录日志并整份跳过；CubeSelection.exclude(Block) 与 registerTargetExclusion(...) 始终优先于资源规则。

二、 核心工作流与生命周期 ​

module.cube 从资源加载到每帧渲染的完整生命周期如下：

  1. 命名空间与永久排除注册（客户端模组构造期）： 调用 CubeSelection.enableNamespace(modId) 将命名空间加入白名单；调用 CubeSelection.exclude(block) 将特定方块加入永久黑名单。
  2. 模型捕获与几何烘焙（资源重载 / 模型烘焙期）：
    • 原版烘焙每个 SimpleModelWrapper 时，Mixin 调用 ModelCapture.remember(...) 用弱键映射（weakKeys）临时记录 UnbakedCuboidGeometry 的 elements 与合成后的 ModelState。
    • 在 ModelEvent.ModifyBakingResult（最低优先级 EventPriority.LOWEST）中，CubeModelEvents.prepare 从资源管理器加载 anvillib/cube_selection.json 合并后的 CubeSelectionRules，再调用 ModelSelections.bake(...) 消费并清空 ModelCapture，遍历所有已启用（model 或 outline 模式）的 BlockState，将旋转长方体解码为 ConvexShape，构建共享 SelectionGeometry（上限 16 MB、32768 个状态）。
    • 在 ModelEvent.BakingCompleted 中，CubeModelEvents.apply 调用 CubeSelection.install(snapshot, rules)（内部再调用 install(snapshot)）原子替换当前生效的模型表与规则，并清空旧的帧缓存与轮廓缓存。
  3. 准星射线精确拾取（每帧 Entity#pick 阶段）： 客户端玩家准星射线检测时，CubePicking.pick(...) 先调用 CubeSelection.beginFrame(level, partialTick) 保证 outline 模式的动态几何也能逐帧刷新，再在 CubeSelection.active() 为 true（存在启用 model 模式的静态或动态方块）时检查当前方块及邻近越界半径（searchRadius()，最大 2 格）内的方块；若 CubeSelection.target(...) 返回有效目标，则在局部空间使用 BVH 与凸多面体平面裁剪求出精确交点与交互面朝向。
  4. 斜棱线描边高亮（每帧 ExtractBlockOutlineRenderStateEvent 阶段）： CubeHighlightEvents.highlight 调用 CubeSelection.outlineTarget(...)（同时响应 model 与 outline 模式）获取当前瞄准方块的轮廓目标，从 OutlineCache 异步获取（或回退使用轻量 fallbackOutline）并集轮廓 PackedOutline，再经 forView(localCamera) 过滤掉小于 0.1/16 像素的微小错位内接缝，最后通过 OutlineRenderer.render 绘制原版线条或高对比度双通道描边。

2. CubeSelection（命名空间、排除规则与全局状态管理） ​

位于 dev.anvilcraft.lib.v2.cube.client.CubeSelection。本节列出其配置与生命周期管理方法（动态部件与查询方法详见下一篇精确拾取与动态部件提供器）：

常量 / 方法签名返回值调用时机、参数说明与边界条件
public static final int MAX_PARTS = 32int单个方块状态（含 multipart 与动态 BER 部件）允许包含的最大 SelectionPart 数量上限。超过 32 个部件时自动回退为原版选择框。
public static void enableNamespace(String namespace)void必须在模型烘焙前调用。校验 namespace 合法性（通过 Identifier.fromNamespaceAndPath(namespace, "cube_selection")）并将其加入启用集合。若 namespace 含非法字符会抛出 IdentifierException。
public static void exclude(Block block)void将指定 Block 加入永久排除集合。被排除的方块既不会在 ModelSelections.bake 中烘焙模型几何，也不会响应动态部件或 modelParts 查询。
public static void registerTargetExclusion(Identifier id, Predicate<BlockState> exclusion)void注册按 id 索引的运行时目标排除规则。
• 同一 id 重复注册会直接替换旧规则；不同 id 互不覆盖。
• 当任意已注册规则对某个 BlockState 返回 true 时，CubeSelection.target(...) 返回 null，精确拾取与高亮立即回退原版。
• 优势：规则在每次帧缓存查询前执行，不影响底层已烘焙的模型缓存；修改客户端配置或注销规则后无需重载资源包即可立即恢复斜棱线。
• 注意：exclusion 回调在每帧渲染与拾取热路径中执行，必须保持无副作用且不得强引用 Level 或 BlockEntity。
public static boolean unregisterTargetExclusion(Identifier id)boolean移除指定 id 的运行时目标排除规则。若此前存在该规则并成功移除则返回 true。不会影响其他 id 的规则或 exclude(Block) 设置的永久排除。
public static boolean isTargetExcluded(BlockState state)boolean检查 state.getBlock() 是否被 exclude(Block) 永久排除，或是否命中任意已注册的 registerTargetExclusion 规则。
public static boolean isEnabled(Block block)boolean判断在结合 exclude(Block)、Java 默认注册（enableNamespace / registerDynamic）及当前 anvillib/cube_selection.json 规则后，block 是否启用模型几何（即最终模式为 MODEL 或 OUTLINE，而非 VANILLA）。
public static boolean supportedBounds(AABB bounds)boolean校验包围盒的所有坐标均为有限浮点数，且整体位于 [-2, 3] 方块坐标范围内（即向周围最多延伸 2 格）。若方块带有原版随机位置偏移（state.hasOffsetFunction()），烘焙和动态注册时会先将 bounds.inflate(0.5) 后再调用此方法校验。
public static void install(ModelSelections.Snapshot snapshot)void安装新的模型烘焙快照，清空 OutlineCache 与当前帧缓存，并仅针对 MODEL 模式方块重新计算精确拾取标记与跨格搜索半径 radius（0 ~ 2）。由 CubeModelEvents.apply 自动调用。
public static void beginFrame(ClientLevel level, float fraction)void重置单帧目标缓存 FRAME，记录当前帧所属的 ClientLevel 与 partialTick 插值系数。
public static void clearWorld()void清空单帧目标缓存与 OutlineCache。在客户端退出存档时由 CubeHighlightEvents.disconnect 自动调用。
public static OutlineCache outlines()OutlineCache获取全局共享的后台轮廓缓存实例。
public static int searchRadius()int获取当前处于 MODEL 模式的模型与动态部件中超出单格 [0, 1] 范围的最大延伸格数（范围 0 ~ 2）。为 0 时 CubePicking 无需扫描邻近越界方块。
public static boolean active()boolean当前快照是否至少存在一个启用 MODEL 模式的静态模型或动态方块提供器（仅配置为 OUTLINE 模式的几何不会触发邻格射线补扫）。
public static boolean extendsBlock(BlockState state)boolean判断处于 MODEL 模式的 BlockState 模型或动态部件包围盒是否超出了 [0, 1]^3 标准单格范围。
public static Statistics statistics()CubeSelection.Statistics返回当前模块的内存与缓存统计快照：states（已缓存状态数）、geometryBytes（共享几何估算字节数）、unsupportedStates（超预算或非凸被跳过的状态数）、outlines（OutlineCache.Statistics）。
