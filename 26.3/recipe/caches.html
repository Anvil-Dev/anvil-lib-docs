世界状态缓存与事务提交 (BlockCache / ItemCache / EntityCache / TagCache) ​

dev/26.3独立版本分支文档
Minecraft 版本26.3
NeoForge 版本26.3.x
Java 要求Java 25+
Maven Artifact 后缀-neoforge-26.3

在世界内配方的多批次匹配与组装过程中，绝对不能边测试边直接修改真实世界中的方块、掉落物或实体——否则一旦后续谓词匹配失败，或者连续执行多批次（如一次铁砧砸落合成 64 组物品）时，会产生大量中间方块更新、掉落物生成与回滚难题。

module.recipe 通过挂载在 InWorldRecipeContext 上的四大缓存（BlockCache、ItemCache、EntityCache、TagCache）构建了一个完整的内存模拟沙箱，直到整次触发的全部批次规划完成、调用 context.accept() 时，才按严格的阶段顺序（order）一次性提交回真实世界。

一、 四大缓存的提交顺序（Commit Order） ​

当调用 InWorldRecipeContext#accept() 时，已注册的 Acceptor 会按 (order, key) 升序依次执行：

阶段顺序 (order)缓存键 (Identifier)执行动作
-100anvillib:entity_validationEntityCache#validate()：在任何世界修改发生前，校验所有待消耗实体仍然存活、非玩家且仍在当前维度（若失效则直接抛错中止整个提交，防止半途失败）。
0anvillib:item_cacheItemCache#endCache()：同步所有被修改的 ItemEntity 与 ResourceHandler<ItemResource> 容器槽位，合并距离 < 0.25 格的同种新增产物并以 ItemEntity 投入世界。
100anvillib:block_cacheBlockCache#accept()：将所有变更的 BlockState 与 BlockEntity NBT 写入世界，对双格方块先以 Block.UPDATE_CLIENTS 抑制中间邻居更新，全部写完后再统一触发 updateNeighborsAt。
150anvillib:entity_cacheEntityCache#commit()：在 EntityDropCapture 拦截作用域内移除被消耗的实体并收集死亡掉落物与经验值。
afterCommit延迟副作用队列在上述所有资源提交全部成功后，依次执行 EntityCache#releaseRewards（生成掉落物与经验球）、SpawnEntity（生成新实体）、ProduceExplosion（产生爆炸）以及 InWorldRecipeCommittedEvent 事件发布。

二、 外部容器如何接入 ItemCache？ ​

除了世界中的地面掉落物（ItemEntity）外，ItemCache 还能直接从触发区域内的**方块实体（BlockEntity）或实体（Entity）**内部槽位读取原料并写入产物。接入方式有如下两种：

  1. 方式 A：实现 ItemResourceHandlerCache 接口（推荐，支持输入/输出分离）： 让你的 BlockEntity 或 Entity 实现 dev.anvilcraft.lib.v2.recipe.cache.ItemResourceHandlerCache 接口，分别返回 getInput() 和 getOutput() 的 NeoForge ResourceHandler<ItemResource>。若输入与输出视图底层指向同一个物理槽位，还可让包装器实现 ItemCacheSlotProvider 以映射回同一物理槽位。
  2. 方式 B：原版 Container + 标签白名单： 若方块实体或实体实现了原版 net.minecraft.world.Container，只需将其类型加入对应标签：
    • 方块实体类型标签：LibBlockEntityTags.ITEM_CACHE（#anvillib:item_cache）
    • 实体类型标签：LibEntityTypeTags.ITEM_CACHE（#anvillib:item_cache） ItemCache 会自动通过 VanillaContainerWrapper.of(container) 将其包装为 ResourceHandler<ItemResource>。

完整代码示例：实现 ItemResourceHandlerCache 与 ItemCacheSlotProvider 的机器方块实体 ​

java
package com.example.mymod.block.entity;

import dev.anvilcraft.lib.v2.recipe.cache.ItemResourceHandlerCache;
import dev.anvilcraft.lib.v2.recipe.cache.item.ItemCacheSlotProvider;
import net.minecraft.core.BlockPos;
import net.minecraft.world.level.block.entity.BlockEntity;
import net.minecraft.world.level.block.entity.BlockEntityType;
import net.minecraft.world.level.block.state.BlockState;
import net.neoforged.neoforge.transfer.ResourceHandler;
import net.neoforged.neoforge.transfer.item.ItemResource;

public class BasinBlockEntity extends BlockEntity implements ItemResourceHandlerCache {
    private final ResourceHandler<ItemResource> physicalInventory;

    public BasinBlockEntity(
        BlockEntityType<?> type,
        BlockPos pos,
        BlockState state,
        ResourceHandler<ItemResource> physicalInventory
    ) {
        super(type, pos, state);
        this.physicalInventory = physicalInventory;
    }

    @Override
    public ResourceHandler<ItemResource> getInput() {
        return this.physicalInventory;
    }

    @Override
    public ResourceHandler<ItemResource> getOutput() {
        return this.physicalInventory;
    }
}
